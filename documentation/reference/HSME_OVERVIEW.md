# HSME — HyperGraph Research Memory Engine

> Поисково-аналитическая система для R&D горно-металлургической отрасли.
> Объединяет внутренние статьи, эксперименты, протоколы и отчёты в единую
> математическую карту знаний с причинно-следственной памятью.

---

## Проблема

Исследовательские институты и R&D-центры в металлургии тонут в документах.
Десятки тысяч отчётов, статей, протоколов — но ответы на простые вопросы
обходятся в часы ручного поиска:

> *«Что уже делали по сплавам X при режиме Y и какой был эффект на свойство Z?»*
> *«Есть ли эксперименты по очистке воды с сульфатами 200–300 мг/л?»*
> *«Какая скорость циркуляции католита оптимальна для никеля?»*

**Почему стандартные решения не работают:**
- **Keyword search** — теряет синонимы, контекст, числовые диапазоны
- **GraphRAG на триплетах** — размазывает один эксперимент по десяткам рёбер,
  теряет целостность контекста, не умеет в числовые диапазоны и контрфакты
- **LLM поверх документов** — галлюцинирует, не ссылается на источники,
  не показывает причинно-следственные цепочки
- **Векторные БД (embedding search)** — не понимают структуры эксперимента
  (вход → процесс → выход), не умеют в интервалы

---

## Решение: HSME

**Гиперграф + VSA (Vector Symbolic Architectures) вместо триплетов.**

Каждый эксперимент — не набор разрозненных связей, а **единый математический
объект**: гиперребро, которое кодируется в один биполярный вектор размерности
10 000 через алгебраические операции (bind → permute → bundle).

```
Документ → NLP-экстракция → Гиперребро (вход/процесс/выход)
                              ↓
                       VSA-кодирование
                              ↓
                    Один вектор эксперимента

Запрос: "никель pH<2" → V_{Ni} ⊗ V_{pH<2}
                              ↓
                   Cosine similarity по всем векторам
                              ↓
                    Результаты + цитаты + уверенность
```

## Ключевая инновация

### Hypergraph-as-a-Vector

Мы не храним триплеты. Мы не эмбеддим чанки текста. Мы превращаем целый
эксперимент (материалы, режимы, оборудование, результаты, доказательства) в
**один математический объект**:

1. **Bind** (⊗) — связываем роль со значением: *Material ⊗ Никель*
2. **Permute** (σ) — сохраняем направленность связей: *σ(Target) ⊗ rel_type ⊗ Source*
3. **Bundle** (⊕) — объединяем всё в гипервектор эксперимента через majority vote

Поиск = кодируем запрос теми же операциями → косинусная близость по всем
экспериментам → **миллисекунды на всём корпусе**.

## Аналитические возможности

### 1. Семантический поиск с интервалами
> *«Показать эксперименты по электроэкстракции никеля при pH 1.5–2.5 после 2020 года»*

Запрос парсится LLM → извлекаются сущности + числа → VSA-интерполяция →
ранжированные результаты с цитатами.

### 2. Контрфактический анализ (Counterfactual Retrieval)
> *«Что изменится, если повысить температуру с 600°C до 700°C?»*

Автоматически находит пары экспериментов, отличающиеся ровно **одним**
параметром, вычисляет дельту свойств. Без LLM-галлюцинаций — на реальных
данных.

### 3. Gap Discovery (поиск пробелов)
> *«Какие комбинации сплав × температура × среда ещё не исследованы?»*

Строит декартову сетку всех известных параметров → находит пустые клетки →
экстраполирует свойства через VSA-близость → LLM генерирует гипотезу.

### 4. Causal Inference (причинный вывод)
> *«Почему при 950°C прочность выросла на 70 МПа?»*

Контрфактная пара → LLM получает δ-параметров и даёт физико-химическое
объяснение с цитатами экспериментов.

### 5. Knowledge Entropy (согласованность)
> *«3 источника подтверждают, 2 противоречат — показать.»*

Система не прячет противоречия, а показывает шкалу согласованности.
Исследователь видит конфликт интерпретаций, а не сглаженный LLM-ответ.

## Ключевые отличия от конкурентов (Market Positioning)

### HSME vs NotebookLM
NotebookLM — про «поговорить с документами». HSME — про **поиск
закономерностей в экспериментальных данных**. У NotebookLM нет графа,
контрфактов, gap analysis, ролевой модели, числовых интервалов.

### HSME vs стандартный GraphRAG (Neo4j + LLM)
GraphRAG строит граф из триплетов — теряет целостность эксперимента, не
умеет в числа и интервалы. HSME кодирует эксперимент как единый вектор:
поиск быстрее, контекст целый, контрфакты — автоматически.

### HSME vs Enterprise Search (Elastic, Algolia)
Keyword search не понимает синонимов, структуры «вход→процесс→выход»,
не умеет находить пробелы в исследованиях. HSME — семантический движок
предметной области.

## Use Cases

1. **Научный сотрудник:** *«Покажи все работы по Au/Ag/PGM distribution между
   штейном и шлаком за последние 5 лет»* → синтез с цитатами + граф.

2. **Технолог:** *«Какие оптимальные скорости циркуляции католита при
   электроэкстракции никеля описаны в литературе?»* → ответ с числами,
   источниками, противоречиями.

3. **Руководитель R&D:** *«Где у нас пробелы в исследованиях по сплавам
   системы Al-Cu?»* → тепловая карта параметров + гипотезы.

4. **Внешний партнёр:** *«Что известно про методы водоподготовки на
   обогатительных фабриках?»* → поиск только по открытым данным.

---

**Инсайт для презентации жюри:** VSA-подход — не просто «тоже работает».
Это фундаментально другой способ представления знаний: не текст, не граф,
а **алгебра научной памяти**. Контрфакты и gap analysis — прямое следствие
этого выбора, а не доработки сверху.
