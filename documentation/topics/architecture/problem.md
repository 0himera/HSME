# Почему HSME выбрал гиперграф + VSA

Публичная архитектурная заметка о том, почему в HSME базовой единицей знания стал
**эксперимент**, а не документный чанк или набор разрозненных триплетов.

---

## Проблема

Для задач вида:

- "что уже делали по материалу X при режиме Y";
- "как это повлияло на свойство Z";
- "какие комбинации параметров изучены слабо";

недостаточно просто искать похожие документы. Нужна модель, которая сохраняет
связность условий опыта: входные параметры, процесс, оборудование, результаты,
источник и контекст.

---

## Принцип решения

В HSME один эксперимент представляется как **целостное гиперребро**:

```text
Experiment =
{
  input_entities,
  process_entities,
  output_entities,
  relations,
  evidence,
  metadata
}
```

Это позволяет не распадаться на десятки независимых "entity -> relation -> entity"
фрагментов и не терять причинно-следственный контекст при поиске.

---

## Почему не только GraphRAG

Триплетный граф хорошо подходит для обхода связей, но плохо сохраняет эксперимент
как атомарное событие. Один и тот же опыт легко размывается между множеством рёбер:

- материал;
- режим;
- установка;
- наблюдаемое свойство;
- публикация;
- авторы.

В HSME Neo4j используется как **дополнительная graph projection** для multi-hop
обогащения и визуализации, а не как единственный источник retrieval.

---

## Почему VSA

Поисковый слой HSME строится на **Vector Symbolic Architecture**:

- `bind` связывает роль и значение;
- `permute` сохраняет направленность relations;
- `bundle` собирает всё в один гипервектор эксперимента.

Упрощённо:

\[
V_{experiment} = \operatorname{bundle}(Role \otimes Value,\ Relations)
\]

Запрос кодируется теми же операциями и сравнивается с экспериментами по
семантическому сходству в `HSMEVectorDatabase`.

Важно: в текущей реализации это **in-memory VSA store на NumPy с pickle-персистентностью**,
а не внешняя vector DB.

---

## Что это даёт на практике

### 1. Поиск по структуре эксперимента

Запросы ищут не просто похожий текст, а комбинации сущностей и свойств:

- материал + процесс;
- процесс + диапазон параметра;
- оборудование + выходное свойство.

Для числовых свойств используется interval-style кодирование, поэтому запросы с
`pH < 2`, температурой или плотностью тока могут сопоставляться не как точное
совпадение строки, а как близкие значения внутри диапазона.

### 2. Контрфактическое сравнение

После retrieval можно находить пары экспериментов, которые различаются ровно одним
входным параметром, и сравнивать изменение результата на реальных данных.

### 3. Gap discovery

Пробелы ищутся не через tensor completion, а через rule-based анализ комбинаций
параметров в `db.analyze_gaps()` с дальнейшей LLM-гипотезой только на финальном шаге.

### 4. Гибрид с Neo4j

Neo4j добавляет:

- публикации и экспертов;
- противоречия;
- multi-hop paths;
- визуализацию графа.

Но если Neo4j недоступен, VSA-поиск продолжает работать сам по себе.

## Текущее архитектурное состояние

```text
Documents -> DocumentParser -> NLPExtractor -> IngestionPipeline
         -> HSMEVectorDatabase (VSA, in-memory)
         -> optional Neo4j dual-write
         -> FastAPI /api/search -> LLM synthesis
```

## Вывод

HSME выбрал связку **гиперграф + VSA + optional Neo4j**, потому что она лучше
сохраняет эксперимент как единицу знания, чем чистый chunk-RAG или чистый граф.

Это делает систему пригодной не только для поиска документов, но и для анализа
режимов, контрфактов, противоречий и исследовательских пробелов.
