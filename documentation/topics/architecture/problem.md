Ваша задача: создать knowledge graph или поисково-аналитическую систему, которая связывает статьи, эксперименты, материалы, свойства, режимы, установки, исследовательские команды и выводы. Вам не нужно вписываться в жесткие рамки — вы сами решаете, какую архитектуру и интерфейс предложить: графовую БД, семантический поиск, гибридное решение. Главное — чтобы система отвечала на вопросы вида: «что уже делали по сплавам X при режиме Y и какой был эффект на свойство Z», показывала связанные сущности, историю решений и пробелы в данных. Для работы вы получите доступ к корпусу внутренних документов, каталогу экспериментов, справочникам материалов и оборудования, перечню сотрудников/лабораторий и тегам тематик. какое решение выбрать для хакатона изящное и необычное? ponder deep. я думаю над таким вариантом: Hyper-Relational GraphRAG (Гиперграфы) + Vector-Symbolic Architectures (VSA).Вот как это работает:1. Гиперребра вместо триплетовВместо обычного графа мы строим гиперграф. Гиперребро может соединять любое количество узлов одновременно.Один эксперимент из документации ложится в базу как одно гиперребро $E = \{v_{Сплав}, v_{Режим}, v_{Установка}, v_{Результат}, v_{Команда}\}$.Вся топология становится сильно разреженной (sparse), но максимально точной. Никакой потери контекста при обходе графа.2. VSA (Алгебраический биндинг смыслов)Как искать по гиперграфам через векторные БД, не перегружая LLM? Через векторно-символьные архитектуры (идеологически это очень близко к SDR в иерархической временной памяти / HTM).Мы не просто храним эмбеддинги чанков. Мы используем алгебраические операции над векторами для "склеивания" сущностей в один плотный репрезентативный вектор:$\mathbf{V}_{experiment} = (\mathbf{V}_{alloy} \otimes \mathbf{V}_{mode}) \oplus \mathbf{V}_{property}$У тебя получается единый математический объект. Когда юзер спрашивает: «что делали по сплавам X при режиме Y», ты генерируешь вектор запроса $\mathbf{V}_{query} = \mathbf{V}_{X} \otimes \mathbf{V}_{Y}$ и ищешь его косинусное сходство по базе готовых гипер-векторов $\mathbf{V}_{experiment}$. Векторная БД (тот же Qdrant) за миллисекунды отдает нужные гиперребра без всякого Beam Search.3. Элегантный Gap-анализ (Латентные пустоты)Как в такой системе искать пробелы в исследованиях?Вместо сравнения деревьев (Tree Edit Distance) мы ищем пустоты в латентном пространстве.Если мы знаем, что векторы успешных экспериментов для группы сплавов образуют определенный манифолд (многообразие) в векторном пространстве, то гэп — это "дырка" в этом манифолде.Мы берем матрицу всех гиперребер (Материалы $\times$ Режимы) и делаем тензорную факторизацию. Там, где тензор предсказывает высокую вероятность связи, но гиперребра физически нет в базе — там и есть слепое пятно, которое нужно исследовать.4. Пайплайн авто-обогащения (Наследование свойств)Если система видит гэп (например, для нового Сплава Б не описано поведение при 1000°C), она находит ближайший топологический аналог (Сплав А) через векторное сходство самих узлов в гиперграфе. LLM получает на вход не сырые куски текста, а готовое смежное гиперребро и промпт: «Экстраполируй этот результат на новый материал».

# HyperGraph Research Memory Engine
### A Next-Generation Knowledge System for Scientific Research

## Идея

Вместо классического **GraphRAG**, где знания представлены набором триплетов (`Entity → Relation → Entity`), система рассматривает **эксперимент как атомарную единицу знания**.

Каждый эксперимент становится единым объектом, содержащим все условия проведения, результаты, источники и степень достоверности.

Таким образом система хранит не отдельные связи, а **целостные научные события**, максимально сохраняя контекст исследования.

# Представление знаний

## Вместо графа

Классический GraphRAG:

```text
Alloy
   │
 tested_in
   │
Mode

Mode
   │
produced
   │
Strength
```

Такой граф теряет контекст эксперимента.

---

## Используется гиперграф

Каждый эксперимент хранится как одно гиперребро.

```text
Experiment #582

{
    Alloy,
    Heat Treatment,
    Temperature,
    Pressure,
    Cooling Rate,
    Furnace,
    Laboratory,
    Operator,
    Property,
    Result,
    Evidence,
    Confidence
}
```

Все параметры принадлежат одному эксперименту и никогда не разделяются.

---

# Причинная память (Causal Memory)

Каждый эксперимент представляется как причинная цепочка.

```text
INPUT

• Alloy
• Temperature
• Pressure
• Cooling
• Machine

        │

        ▼

PROCESS

Heat Treatment

        │

        ▼

OUTPUT

• Yield Strength
• Hardness
• Grain Size
• Crack Density

        │

        ▼

EVIDENCE

• Article
• Images
• SEM
• XRD

        │

        ▼

Confidence Score
```

Таким образом система понимает не просто связи между объектами, а причинно-следственные зависимости.

---

# Hypervector Encoding (VSA)

Каждый эксперимент кодируется в один гипервектор.

Вместо хранения отдельных embedding'ов документов используются операции связывания смыслов.

Например:

\[
V_{experiment} =
((V_{alloy} \otimes V_{temperature})
\otimes V_{pressure})
\oplus
V_{property}
\]

где

- ⊗ — Binding (связывание сущностей)
- ⊕ — Bundling (объединение информации)

Получается компактное математическое представление целого эксперимента.

---

# Поиск

Пользователь спрашивает:

> Что исследовали для сплава X при режиме Y?

Формируется гипервектор запроса

\[
V_{query}=V_X \otimes V_Y
\]

Qdrant ищет ближайшие гипервекторы экспериментов.

LLM получает уже не документы, а связанные научные события.

---

# Counterfactual Retrieval

Главная особенность системы.

Она ищет эксперименты, отличающиеся только одним параметром.

Например

```text
Experiment A

Alloy A
900°C
Oil Cooling

↓

Strength = 620 MPa
```

```text
Experiment B

Alloy A
950°C
Oil Cooling

↓

Strength = 690 MPa
```

Отличается только температура.

Следовательно система автоматически делает вывод:

```text
ΔTemperature

↓

ΔStrength
```

Получается объяснимое изменение свойства, основанное на реальных данных, а не на генерации LLM.

---

# Tensor Representation

Все эксперименты одновременно формируют большой разреженный тензор.

Например

```text
(Material)

×

(Temperature)

×

(Cooling)

×

(Pressure)

×

(Equipment)

↓

Measured Property
```

Каждая заполненная клетка соответствует существующему эксперименту.

# Research Gap Discovery

Для поиска пробелов используется **Tensor Completion**.

Если модель предсказывает высокую вероятность существования комбинации параметров, но соответствующего эксперимента нет, система помечает её как перспективное направление исследования.

Например

```text
Alloy A

900°C

Oil Cooling

✓
```

```text
Alloy A

950°C

Oil Cooling

✓
```

```text
Alloy A

1000°C

Oil Cooling

?
```

Если вероятность существования такой комбинации высока, система сообщает:

> Вероятный исследовательский пробел.

Таким образом пробел определяется математически, а не просто отсутствием документа.

# Knowledge Entropy

Система оценивает степень определённости знаний.

### Низкая энтропия

```text
5 экспериментов

↓

Все показывают одинаковый результат
```

Высокая уверенность.

---

### Высокая энтропия

```text
5 экспериментов

↓

620 MPa

↓

710 MPa

↓

540 MPa

↓

690 MPa
```

Результаты противоречат друг другу.

Система сообщает:

> Данные неоднозначны. Требуются дополнительные исследования.

---

# Auto-Enrichment

Если найден исследовательский пробел,

система:

1. Находит наиболее похожие материалы.
2. Извлекает их гиперребра.
3. Передает их в LLM.
4. LLM строит гипотезу для нового материала.

Например:

> Для сплава B отсутствуют данные при 1000°C.

Находится похожий сплав A.

LLM получает:

> Экстраполируй известный эксперимент на новый материал с указанием степени уверенности.

---

# Ответ пользователю

На запрос

система возвращает:

- историю исследований;
- подтверждающие документы;
- степень уверенности;

# Отличия от классического GraphRAG

| GraphRAG | HyperGraph Research Memory Engine |
|-----------|-----------------------------------|
| Документы | Научные события |
| Триплеты | Гиперребра |
| Поиск документов | Поиск экспериментов |
| Связи между сущностями | Причинные зависимости |
| Embedding документов | Hypervector Encoding |
| Обычный RAG | Counterfactual Retrieval |
| Нет анализа пробелов | Tensor Completion |
| Ответ LLM | Научное объяснение с историей решений |

# Технологический стек

- **LLM** — извлечение сущностей и научное рассуждение
- **Hypergraph** — представление экспериментов
- **Vector Symbolic Architecture (VSA)** — кодирование гиперребер
- **Qdrant** — поиск по гипервекторам
- **Tensor Completion** — обнаружение пробелов в исследованиях
- **Counterfactual Retrieval** — объяснимое сравнение экспериментов
- **Knowledge Entropy** — оценка неопределенности научных данных

---

# Ключевая идея

Система представляет знания не как набор документов и не как граф сущностей, а как **научную память**, где каждая запись является целостным экспериментом с причинно-следственными связями.

Это позволяет не только искать существующие результаты, но и объяснять их, выявлять противоречия, находить отсутствующие исследования и предлагать новые направления для экспериментов.
