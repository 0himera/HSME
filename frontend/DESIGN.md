# HSME — концепция UX «Инженерный атлас»

UX-модель — NotebookLM, перенесённый из мира «документов» в мир «экспериментов»:
пользователь собирает корпус, разговаривает с ним на естественном языке, а система
отвечает не текстом-галлюцинацией, а синтезом из гиперрёбер с цитатами, уверенностью
и артефактами (граф, карта пробелов, контрфакты, отчёт).

---

## 1. Layout: три панели (как в NotebookLM)

```
┌────────────┬──────────────────────────────┬──────────────┐
│  КОРПУС    │          ДИАЛОГ              │   СТУДИЯ     │
│ (sources)  │        (chat + answer)       │  (artifacts) │
├────────────┼──────────────────────────────┼──────────────┤
│ документы   │ вопрос на естественном языке │ граф знаний  │
│ эксперименты│ → синтез с цитатами [Э-582]  │ карта        │
│ фильтры:    │ → шкала согласованности      │  пробелов    │
│  РФ/Мир,    │ → контрфактная пара (Δ)      │ контрфакты   │
│  год,       │ → чипы сущностей             │ экспорт      │
│  достовер-  │ → follow-up подсказки        │  литобзора   │
│  ность      │                              │ закреплённые │
│ роль юзера  │                              │  гипотезы    │
└────────────┴──────────────────────────────┴──────────────┘
```

### Левая панель — «Корпус»
- Список загруженных документов (`GET /api/documents`) с чекбоксами — как sources
  в NotebookLM: ответ строится только по выбранным.
- Фильтры-чипы: география (РФ / Мир — требование ТЗ), диапазон лет, тип документа,
  порог достоверности.
- Внизу — счётчик «N документов · M экспериментов» (`GET /api/statistics`)
  и переключатель роли (Администратор / Аналитик / Исследователь / Внешний партнёр →
  заголовки `X-User-Name` / `X-User-Role`).

### Центр — «Диалог»
- Одно поле ввода: «Спросите про материалы, режимы, свойства…» (`POST /api/search`).
- Ответ — **не список результатов, а синтез**: абзац в серифе, где каждое утверждение
  снабжено кликабельной цитатой-чипом `[Э-582]`, числовые значения — в моноширинном.
- Под ответом:
  - **Шкала согласованности** (knowledge entropy): «5 источников подтверждают ·
    2 противоречат — показать». Клик раскрывает противоречивые эксперименты.
  - **Контрфактная вставка** (`GET /api/counterfactuals/{id}`): пара экспериментов,
    отличающихся одним параметром, с дельтой: `Δ +10 °C → +1.7 п.п. выхода по току`.
  - Чипы извлечённых сущностей (Материал / Процесс / Параметр) — клик = новый фильтр.
  - Подсказки follow-up вопросов.
- Клик по цитате `[Э-582]` → **Паспорт эксперимента** (модалка/панель):
  причинная цепочка Вход → Процесс → Выход → Доказательства + штамп
  (шифр, источник, лаборатория, год, гриф доступа, достоверность).

### Правая панель — «Студия»
Артефакты, порождаемые из текущего диалога (аналог Audio Overview / Notes в NotebookLM):
- **Граф знаний** — мини-превью, клик разворачивает на весь центр (`GET /api/graph`).
- **Карта пробелов** — теплокарта Материал × Режим, «дырки» подсвечены; клик по ячейке
  `?` → генерация гипотезы (`POST /api/gaps`, `POST /api/enrich-gap`).
- **Контрфакты** — счётчик найденных пар, клик — список diff-карточек.
- **Экспорт литобзора** — PDF / Markdown (пожелание ТЗ).
- **Закреплённые гипотезы** — сгенерированные LLM-гипотезы можно «приколоть» и они
  остаются между сессиями (научный блокнот).

## 2. Демо-сценарий для жюри (5 минут)

1. Вопрос: «Какие решения циркуляции католита при электроэкстракции никеля описаны,
   и какая скорость оптимальна?» → синтез с цитатами и числами.
2. Клик по цитате → паспорт эксперимента с причинной цепочкой и достоверностью.
3. Шкала согласованности показывает противоречие → раскрываем два конфликтующих
   эксперимента (killer-фича «конфликт интерпретаций» из проблематики ТЗ).
4. Контрфактная пара: «отличается только температура → вот дельта» — объяснимость.
5. Карта пробелов: ячейка `Сплав А × 1000 °C = ?` → кнопка «Сгенерировать гипотезу».
6. Переключаем роль на «Внешний партнёр» — внутренние отчёты исчезают из корпуса
   и графа вживую (демо ролевой модели).

## 3.0. Реализованная тема: «Ночная смена» (тёмный вариант атласа)

Реализация в Next.js пошла по тёмной версии палитры (см. `app/globals.css`, все токены — CSS-переменные):

| Роль | Токен | Hex |
|---|---|---|
| Фон страницы (тёплый графит) | `--bg` | `#14110E` |
| Панели / карточки | `--panel` / `--card` | `#191512` / `#211C17` |
| Чернила / вторичный / приглушённый | `--ink` / `--ink-2` / `--ink-3` | `#E9E1D0` / `#A89D87` / `#746A58` |
| Линии | `--line` / `--line-strong` | `#2E2820` / `#3C332A` |
| Медь (действия, цитаты) | `--copper`, `--copper-bright` | `#C98A52`, `#E2A76E` |
| Никель (данные, ссылки) | `--nickel` | `#8FA9B8` |
| Малахит (консенсус) | `--malachite` | `#5FA98C` |
| Оксид (противоречия, гриф) | `--oxide` | `#CD7355` |
| Сера (пробелы, гипотезы) | `--sulfur` | `#D8A848` |

Эффекты: кастомный курсор-визир (точка + кольцо с лерпом, режимы hover/text/press),
зерно плёнки поверх всего, «дыхание печи» (тёплое свечение снизу), фоновое созвездие
гиперграфа на canvas, sheen-блик на медных кнопках, stagger-появление списков,
анимированные чекбоксы, скелетоны загрузки, шаги «мышления» VSA-ядра, анимированные
шкалы согласованности и достоверности. Шрифты IBM Plex захостены локально
(`public/fonts`) — демо не зависит от интернета.

## 3. Визуальный стиль: «Инженерный атлас» (светлый вариант — референс)

Анти-тренд: **никакого неона, тёмного glassmorphism и градиентов** — это будет у всех.
Вместо этого — эстетика научного издательства + техническая документация НИИ:
светлая «бумага», графитовые чернила, акценты цветов металлов. Выглядит как
инструмент, которому доверяют, и отлично смотрится в презентации/печати.

### Палитра
| Роль | Цвет | Hex |
|---|---|---|
| Фон страницы («бумага») | тёплый светлый | `#F2EEE6` |
| Панели | слоновая кость | `#F7F4EC` |
| Карточки | белый | `#FFFFFF` |
| Текст («чернила») | графит | `#221F1A` |
| Вторичный текст | тёплый серый | `#8A8375` |
| Линии (hairline) | пергамент | `#D8D2C4` |
| Акцент действия — **медь** | | `#A45C2A` |
| Ссылки/данные — **никель** (сталь) | | `#46606E` |
| Консенсус — **малахит** | | `#2E6E5A` |
| Противоречие — **оксид** | | `#9C3B2E` |
| Пробел/гипотеза — **сера/янтарь** | | `#B98A2F` |

Семантика металлов = предметная область (медь, никель, малахит) — жюри это считает.

### Типографика (IBM Plex — полная кириллица, научный характер)
- **IBM Plex Serif** — голос системы: синтезированные ответы, заголовки, гипотезы.
- **IBM Plex Sans** — UI: панели, кнопки, фильтры.
- **IBM Plex Mono** — данные: числа, единицы, шифры (`Э-582`, `300 А/м²`), цитаты.

### Компоненты-фишки
- **Паспорт эксперимента** оформлен как лист техдокументации со «штампом» внизу
  (шифр · источник · лаборатория · исполнитель · год · гриф) — узнаваемо для отрасли.
- **Цитаты-чипы** `[Э-582]` — медная рамка, mono, ховер показывает фрагмент источника.
- **Шкала согласованности** — тонкая полоса малахит/оксид, не «прогресс-бар».
- Hairline-границы 1px, радиусы 6–8px, теней нет (максимум 1px смещение у модалок).
- Анимации — только «чернильные»: fade/slide 150–200 мс, без пружин и свечения.

## 4. Маппинг на существующий API

| UI | Эндпоинт |
|---|---|
| Список корпуса | `GET /api/documents`, `GET /api/experiments` |
| Диалоговый поиск | `POST /api/search` (принимает свободный текст) |
| Граф | `GET /api/graph` |
| Счётчики | `GET /api/statistics` |
| Карта пробелов / гипотеза | `POST /api/gaps`, `POST /api/enrich-gap` |
| Контрфакты / объяснение | `GET /api/counterfactuals/{id}`, `GET /api/reason/{id}` |
| Роли | заголовки `X-User-Name`, `X-User-Role` |
| Аудит (для роли админа) | `GET /api/audit-logs` |

## 5. Приоритеты до дедлайна (impact / effort)

1. Каркас 3 панелей + диалоговый поиск с цитатами и чипами сущностей.
2. Паспорт эксперимента (модалка) — самый «продающий» экран.
3. Шкала согласованности + контрфактная вставка в ответ.
4. Карта пробелов (теплокарта) + кнопка «Сгенерировать гипотезу».
5. Переключатель ролей с живым скрытием данных.
6. Граф — оставить Vis.js, но перекрасить в палитру атласа (бумага/медь/никель).
7. Экспорт в Markdown (кнопка «Скопировать литобзор») — дёшево, закрывает пункт ТЗ.
